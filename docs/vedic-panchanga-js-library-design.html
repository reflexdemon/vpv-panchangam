A TypeScript port of the Drik Panchang + Kundali calculator for Node.js

📅 2026-07-05 💻 TypeScript · swisseph 🌐 3 locales bundled (en · hi · ta) ⚡ ~7,900 LOC estimate

1 Overview

The Vedic Panchanga JS Library is a faithful TypeScript port of the vedicpanchanga.com Python backend. It computes the full Drik Panchang (daily calendar) and Kundali (birth chart) using swisseph for astronomical calculations and pure TypeScript for everything else.

4 Public API

1. computeDetailedPanchang() — Daily Drik Panchang
computeDetailedPanchang( date?: string, // "YYYY-MM-DD", default: today latitude: number, longitude: number, timezone?: string, // IANA, e.g. "America/New_York" locale?: Locale // "en" | "hi" | "ta", default: "en" ): Promise<PanchangResponse>

Returns sunrise/sunset, five limbs (tithi/nakshatra/yoga/karana/vara), sequences, muhurta timings, Rahu Kalam, Gowri, Hora, Tyajyam, Nalla Neram, Tarabalam, Chandrabalam, calendars, and more.

2. computeChart() — Full Birth Chart (Kundali)
computeChart( birthInfo: BirthInfo, // date, time, lat, lon, tz, ayanamsa locale?: Locale ): Promise<ChartResponse>

Returns planetary positions, 17 divisional charts, Vimshottari Dasha (Mahadasha + Antardasha), Ashtakavarga, Jaimini Karakas, Karakamsa, Swamsa, friendships, aspects, Kalsarpa.

6 Panchang Calculation Flow

computeDetailedPanchang(date, lat, lon, tz, locale) └ Resolve timezone → IANA tz, Julian Day at local midnight └ Rise/Set → sunrise, sunset, moonrise, moonset, next_sunrise └ Vara → weekday from sunrise └ Five Limbs in window [sunrise, next_sunrise) └ Tithi → (moon - sun) / 12° with bisection boundaries └ Nakshatra → moon / 13.333° with bisection └ Yoga → (sun + moon) / 13.333° └ Karana → (moon - sun) / 6° └ Moon Sign → moon / 30° └ Inauspicious └ Rahu Kalam / Yamaganda / Gulika (8-segment day) └ Dur Muhurtam, Bhadra, Varjyam └ Auspicious └ Brahma / Abhijit / Vijay / Godhuli / Nishita └ Amrit Kalam, Siddhi Yogas └ Tyajyam → nakshatra + tithi + vara + amritadi + lagna + karana + gowri + dosha + tithi-lagna + tamil-month └ Gowri / Hora / Nalla Neram └ Calendars → Shaka, Vikram, Kali, National, Tamil └ Locale resolution → all named entities in requested language

7 Chart (Kundali) Calculation Flow

computeChart(birthInfo, locale) └ Parse inputs → local time → UTC → Julian Day └ Compute planets → calc_ut for Sun..Pluto + Rahu (mean node) └ Ketu → Rahu + 180° └ Combustion → within 5° of Sun └ Ascendant → houses_ex with sidereal flag └ Houses → whole sign from ascendant └ Vargas (17 charts) └ For each planet + varga: compute divisional sign + degree └ Build house map per varga (planets relative to div. ascendant) └ Dasha → from Moon's nakshatra, balance at birth └ Ashtakavarga → BAV + SAV from contributor rules └ Placements → exaltation/debilitation/own_sign/moolatrikona/vargottama/digbala/pushkara/gandanta/neechabhanga/parivartana/graha-yuddha └ Jaimini → 7 karakas (degree rank) + Karakamsa + Swamsa └ Friendships → natural + temporal + composite (Panchadha) └ Aspects → 7th + special, strength 0–100 └ Kalsarpa → all planets on one side of Rahu-Ketu axis

8 Bisection Search Engine

The single most critical algorithm — used by every sequence generator (tithi, nakshatra, yoga, karana, moonsign, udaya lagna) to find the exact moment an angle crosses a target degree.

// Core algorithm: find JD when angleFn(jd) reaches targetDeg function findAngleTime( lo: number, // start JD hi: number, // end JD targetDeg: number, // target angle 0-360 angleFn: AngleFn // (jd) => angle in degrees ): number | null { let fLo = angleFn(lo); let fHi = angleFn(hi); // Check for crossing considering 360° wrap const wraps = Math.floor((targetDeg + 360 - fLo) / 360); const expected = Math.floor((fHi + 360 - targetDeg) / 360); if (expected <= wraps) return null; // no crossing // Binary search (~40 iterations, 1e-8 JD ≈ 0.9ms) for (let i = 0; i < 40; i++) { const mid = (lo + hi) / 2; const diff = normalizeDiff(targetDeg - angleFn(mid)); if (diff > 0) lo = mid; else hi = mid; if (hi - lo < 1e-8) break; } return (lo + hi) / 2; } // Angle functions used: // "tithi": (moon - sun) % 360 // "moon": moon % 360 // "sun": sun % 360 // "yoga": (sun + moon) % 360

15 Dependencies

Runtime swisseph ^2.x Swiss Ephemeris (planetary positions, houses, rise/set, eclipses)
Dev only typescript, vitest, eslint, prettier

Zero runtime dependencies beyond swisseph. All calendar/astrological calculations are pure TypeScript. The timezone parameter is optional — if omitted, defaults to "UTC". Unlike the Python backend, this library does not bundle coordinate-to-timezone lookup. Users who need it should pass the IANA timezone explicitly or provide it via geo-tz.
