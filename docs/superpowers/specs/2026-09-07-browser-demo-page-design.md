# Browser Demo Page (Panchang + Kundali) Design

Date: 2026-09-07
Status: Approved (design) — implementation pending

## Objective

Add an `example/` folder with a single-page interactive demo that consumes the
library **from source** (not the published package) and demonstrates **every
public feature** of `computeDetailedPanchang` and `computeChart`:

- Full Drik Panchang (Tithi, Nakshatra, Yoga, Karana, Vara, Moon sign, Sun sign)
- Auspicious timings (Brahma Muhurta, Abhijit, Vijay, Godhuli, Nishita,
  Amrit Kalam, Sarvartha/Amrita Siddhi Yoga)
- Inauspicious timings (Rahu Kalam, Yamaganda, Gulika, Dur Muhurtam, Bhadra, Varjyam)
- Gowri Panchangam (8+8 segments) and Planetary Hora (12+12)
- Nalla Neram
- Tyajyam: all 10 types
- Calendars (Shaka, Vikram, Kali, Gujarati, National Civil, Nirayana solar,
  Lunar month) + Tamil calendar
- Ritu/Ayana, Chandra Vasa, Disha Shool, Rahu Vasa
- Birth chart: all 17 divisional charts (D1-D60, incl. D11)
- Vimshottari Dasha (Mahadasha + Antardasha + Pratyantar)
- Ashtakavarga (BAV + SAV)
- Special placements (exaltation, debilitation, own sign, moolatrikona,
  vargottama, digbala, pushkara, mrityu bhaga, gandanta, neecha bhanga,
  parivartana, graha yuddha)
- Jaimini Chara Karakas + Karakamsa/Swamsa
- Planetary friendships (natural, temporal, composite)
- Graha Drishti (aspects with strength)
- Kalsarpa Yoga detection
- Locales: en (`en`), Hindi/Devanagari (`hi`), Tamil (`ta`)

Two hard requirements from the user:

1. Every feature demo is accompanied by a **TypeScript snippet showing the exact
   input used** for that demo (generated live from the current control-panel
   state).
2. The demo is **auto-deployed to GitHub Pages** on every push to `main`
   (covers merges and direct commits).

## Approach

- Bundle the library **source** (`src/index.ts`) with esbuild into a single
  browser IIFE exposing the global `vpv`.
- The demo `index.html` is plain HTML + `<script>` and loads ECharts and
  highlight.js from a CDN for charts and syntax highlighting.
- Everything is served over **HTTP** (never `file://`), because the
  `@swisseph/browser` WASM sidecar is loaded via `fetch()` of a relative URL.
- Interactive control panel recomputes both the Panchang and Kundali tabs live.

## Build & Serve

### esbuild bundle

Command (new npm script `example:build`):

```
esbuild example/entry.ts --bundle --format=esm \
  --platform=browser --outfile=example/dist/vpv-demo.mjs \
  --external:node:*
```

- `example/entry.ts` imports `src/index.ts` (the public API barrel) and assigns
  `window.vpv` with `computeDetailedPanchang`, `computeChart`,
  `PanchangError`/`ChartError`, locale tables, and `EphemerisService`.
- Built as an **ES module**, not an IIFE: `@swisseph/browser` locates its WASM
  through `new URL("./swisseph.wasm", import.meta.url)`, and an IIFE bundle
  would neutralise `import.meta` (the wasm would fall back to the page URL and
  ​404). `.mjs` keeps `import.meta.url` intact; both page scripts are
  `type=module` so the bundle runs before `app.js`.
- `node:*` modules are external; in the browser they are never evaluated
  (the fetch-shim guard short-circuits before importing them).
- `scripts/copy-demo-wasm.cjs` (run by `example:build`) copies
  `node_modules/@swisseph/browser/dist/swisseph.wasm` into `example/dist/`
  next to the bundle.
- esbuild (^0.21.x, already vendored via vite) is added as an explicit dev
  dependency rather than relying on the transitive copy.

### npm scripts

- `example:build` — the esbuild command above + the wasm copy step.
- `demo` — `npm run example:build && node example/serve.js`
- `demo:watch` — copies the wasm, rebuilds `example/dist/vpv-demo.mjs` on
  source change and runs `example/serve.js` (`esbuild ... --watch`).
- `serve.js` — small dependency-free static server (`node:http` + `node:fs`,
  MIME map) serving the `example/` directory, default port 8080, overridable
  via `PORT` env. Provides the wasm MIME type.

### File layout

```
example/
  index.html     # layout, tabs, controls, section mount points, inline CSS
  entry.ts       # ESM entry: exports src barrel into window.vpv
  app.js         # all demo logic (module script; globals: vpv, echarts, hljs)
  serve.js       # dependency-free static server
  README.md      # how to run + one-time GitHub Pages setup
  dist/          # generated by example:build (gitignored)
     vpv-demo.mjs
     swisseph.wasm
.github/workflows/deploy-demo.yml
scripts/copy-demo-wasm.cjs
```

`example/dist/` is added to `.gitignore`.

## Page Architecture

### index.html

- Loads from CDN (jsDelivr or unpkg):
  - ECharts 5 (`echarts.min.js`)
  - highlight.js core + TS language + CSS theme
- Loads `./dist/vpv-demo.mjs` then `./app.js` (both `type=module`) —
  **relative paths only** so the same page works over `serve.js`, any static
  server, and the deployed path `https://<user>.github.io/vpv-panchangam/`.
- Controls: date, time (HH:MM), latitude, longitude, timezone (input with
  sensible default), ayanamsa select (Kundali), locale select (en/hi/ta).
  Defaults: Ujjain (23.1765, 75.7885), today's date, 12:00, Asia/Kolkata,
  lahiri, en.
- Tabs: "Panchang" and "Kundali".
- A status/error banner area for API failures.

### app.js

- `state` object holds the control values; every mutation re-renders the
  active tab.
- On each render: `computeDetailedPanchang(date, lat, lon, tz, locale)` (or
  `computeChart(birthInfo, locale)`) is awaited inside try/catch. Errors
  (`PanchangError`, `ChartError`) render the `name + code` in the banner.
- A declarative "section spec" list drives Panchang rendering: each entry has
  an id, title, a render function (reads fields from the response), and a code
  snippet generator.
- Section snippet generator returns the exact TS call using the *current*
  control values, e.g.:

  ```ts
  const p = await computeDetailedPanchang("2026-09-07", 23.1765, 75.7885, "Asia/Kolkata", "en");
  p.panchang.tithi   // current tithi
  ```

  Snippets are inserted into `<pre><code class="language-ts">` blocks and
  highlighted with `hljs.highlightElement`.
- ECharts instance lifecycle: `echarts.getInstanceByDom(el)` reuse, `dispose`
  before re-render to avoid leaks.

## Panchang Tab Sections

1. Header — date, location, timezone, locale.
2. Sun & Moon timings — `sun_moon` (sunrise, sunset, moonrise, moonset,
   next sunrise, dinaman/ratriman hours, madhyahna).
3. Vara + Paksha — `vara`, `panchang.paksha`.
4. Panchang — `panchang.{tithi, nakshatra, yoga, karana}` (current) with a
   next-5 sequence table for each from `*_sequence`.
5. Rashi & Nakshatra — `rashi_nakshatra` (moonsign + sequence, sunsign,
   surya_nakshatra, moon_nakshatra_padas).
6. Calendars — `lunar_month` (shaka/vikram/gujarati samvat, chandramasa
   amanta + purnimanta, paksha, pravishte day, nirayana solar month),
   `calendars` (kali year + ahargana, JD, MJD, rata die, ayanamsha,
   national civil date, national nirayana date), `tamil_calendar`.
7. Ritu & Ayana — `ritu_ayana` (drik + vedic).
8. Auspicious timings — `auspicious_timings` cards (brahma_muhurta,
   pratah_sandhya, abhijit, vijay_muhurta, godhuli_muhurta, sayahna_sandhya,
   nishita_muhurta, amrit_kalam[], sarvartha_siddhi_yoga[], amrita_siddhi_yoga[]).
9. Inauspicious timings — `inauspicious_timings` cards (rahu_kalam,
   yamaganda, gulika_kalam, dur_muhurtam[], bhadra[], varjyam[]).
10. Udaya Lagna — `udaya_lagna` table.
11. Chandra & Tara balam — `chandrabalam.good_rashis`, `tarabalam.good_nakshatras`
    chips.
12. Shool & Vasa — `shool_vasa` (disha_shool, rahu_vasa, chandra_vasa).
13. Yogas extra — `yogas_extra.ganda_mula`, `yogas_extra.ravi_yoga`.
14. Gowri Panchangam — `gowri_panchang` day/night, each 8 segments, rendered
    as an ECharts horizontal segment strip (green = auspicious, red = not).
15. Hora — `hora` day/night (12+12) segment strip.
16. Nalla Neram — `nalla_neram[]` ECharts timeline strip.
17. Tyajyam — all 10 types via `tyajyam`: nakshatra[], tithi[], vara,
    amritadi_yogam[], lagna[], karana[], gowri[], dosha[], tithi_lagna[],
    tamil_month_avoidables. Each rendered as a mini table or timeline.
18. Day-at-a-glance — merged 24h ECharts strip color-coding every
    auspicious/inauspicious window from 8/9/14/15/16 for the full-day context.

Every section includes its exact-input TS snippet.

## Kundali Tab Sections

Inputs: `computeChart({ date, time, latitude, longitude, timezone, ayanamsa }, locale)`.

1. Birth details — `birth` (local/UTC times, tz, coords, JD, ayanamsa value + id + label).
2. D1 rashi wheel — ECharts **polar** chart with the 12 rashi sectors and
   planets/-nodes placed at their longitudes (Su Mo Ma Me Ju Ve Sa Ra Ke),
   plus a classic **North Indian** grid rendering (fixed squares for
   movable/fixed/dual rashi with ascendant marker) via CSS grid.
3. Planet table — `ascendant` + `planets_data`; columns: body, sign (+rashi),
   degree in sign (dms), nakshatra (+pada), house, and every special-placement
   flag as a badge: exalted, debilitated, own_sign, moolatrikona, vargottama,
   digbala, pushkara_bhaga, mrityu_bhaga, gandanta, neecha_bhanga, parivartana
   (+ with which), graha_yuddha (+ with which). Retrograde / combust markers.
4. Divisional charts gallery — `vargas` + `varga_order`; renders all 17 charts
   (D1, D2, D3, D4, D7, D9, D10, D12, D16, D20, D24, D27, D30, D40, D45, D60,
   D11) as North-Indian grid cells (house → planet abbreviations via `chart`,
   `asc_sign` marked), each with `name` + `subtitle`.
5. Vimshottari Dasha — `dasha` table (mahadasha rows) with expandable
   `antardashas` (and their `pratyantars`); plus an ECharts timeline of the
   mahadasha periods.
6. Jaimini — `karakas` (7 rows: rank/title/planet/sign/degree) plus
   `karakamsa` and `swamsa` callouts.
7. Friendships — `friendships` as three matrices (natural, temporal,
   composite) rendered as colored grids (F/N/E and GF/GE for composite) with a
   legend.
8. Drishti — `drishti.aspects`/`by_planet` table (aspect type, offset, sign,
   house, strength, benefic) + `drishti.mutual` pairs, with strength as a bar.
9. Kalsarpa — `kalsarpa` verdict card (present, kind, direction, rahu/ketu
   houses).
10. Ashtakavarga — `ashtakavarga.bav` per-planet 12-bin bar charts (7 small
    ECharts bars) + `ashtakavarga.sav` summary bar chart; values directly
    labeled.

Every section includes its exact-input TS snippet.

## Code-Snippet Generation (both tabs)

- The snippet is a function of `state` at render time, so it always matches
  what is displayed.
- Panchang snippets: single `computeDetailedPanchang(...)` call with the
  current date/lat/lon/tz/locale (locale passed as the 5th arg `"en"|"hi"|"ta"`),
  followed by one or two field accesses for that section.
- Kundali snippets: single `computeChart({...})` object literal with current
  date/time coords/tz/ayanamsa, followed by the section's field accesses.
- The objects are printed with the same shapes the library returns (e.g.
  `p.gowri_panchang.day`).
- Valid snippet JSON interpolation is done with a small formatter; no
  external template engine.

## Error Handling

- Both `computeDetailedPanchang` and `computeChart` are awaited inside
  try/catch; `PanchangError` / `ChartError` display `name` + `.code` + message
  in the banner and the section shows an unobtrusive placeholder.
- Any unexpected render error is caught and logged to console with a visible
  banner.
- The banner is cleared on the next successful render.

## GitHub Pages Deployment

New file `.github/workflows/deploy-demo.yml`:

```yaml
name: deploy-demo
on:
  push:
    branches: [main]
  workflow_dispatch:

permissions:
  contents: write

jobs:
  deploy:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with: { node-version: 22 }
      - run: npm ci
      - run: npm run example:build
      - uses: peaceiris/actions-gh-pages@v4
        with:
          github_token: ${{ secrets.GITHUB_TOKEN }}
          publish_dir: example
          publish_branch: gh-pages
```

- Trigger: any push to `main` (merges and direct commits) + manual dispatch.
- Builds the bundle from source, then publishes the `example/` folder
  (index.html, app.js, dist/vpv-demo.mjs, swisseph.wasm) to the `gh-pages`
  branch (`.nojekyll` added by the action so the wasm is served as-is).
- Relative paths in index.html make the deployed page identical to the local
  one, so the ECharts/highlight.js CDN loads and the wasm resolves from
  `.../dist/swisseph.wasm`.
- One-time manual setup (documented in example/README.md):
  Settings → Pages → Source = "Deploy from a branch" → branch `gh-pages`, `/`.

## Deliverables / Non-Goals

Deliverables:
- `example/{index.html,app.js,serve.js,README.md}`
- `.github/workflows/deploy-demo.yml`
- `package.json` scripts (`example:build`, `demo`, `demo:watch`) + `esbuild`
  devDependency
- `.gitignore` entry for `example/dist/`

Non-goals:
- No changes to the library's public API, `src/`, or behavior.
- No bundler/vite setup for the example beyond the single esbuild command.
- No test suite for the demo page (verified manually + smoke checks); existing
  library test suite must stay green.

## Implementation notes (deviations from the spec above)

- **Bundle format: ESM, not IIFE.** `@swisseph/browser` locates its WASM via
  `new URL("./swisseph.wasm", import.meta.url)`. In an IIFE bundle esbuild
  rewrites `import.meta` to an empty object, so the fallback path
  `"swisseph.wasm"` would resolve against the **page** URL and 404. Building as
  an ES module keeps `import.meta.url` intact, so the sidecar resolves relative
  to the bundle (`example/dist/swisseph.wasm`). A tiny `example/entry.ts`
  (instead of `--global-name`) assigns the public surface to `window.vpv`.
  Both page scripts are loaded as `type=module` so ordering is guaranteed.
  `scripts/copy-demo-wasm.cjs` copies the wasm next to the bundle during
  `example:build` (the library itself does not emit a wasm asset).
- **All vargas use the South-Indian fixed-sign grid.** The spec described a
  "North Indian diamond" layout, but that layout is ambiguous; the fixed-sign
  4×4 grid (corners empty, Aries fixed at left-middle, ascendant marked ▲) is
  layout-independent and unambiguous for every divisional chart (D1–D60).
- **One-time Pages setup is required** (documented in `example/README.md`):
  the demo directory must be enabled from Settings → Pages before the
  workflow's first deploy.
